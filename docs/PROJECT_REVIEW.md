# 專案初步審查（2026-10-24）

本文件審查 `PROJECT_PROPOSAL.md` 與 `DEVELOPMENT_BLUEPRINT.md` 的研究設計和可實作性。目前資料夾沒有 Git Repository、程式碼、鎖定版本或行情資料，因此這是**規格審查**，不是已完成的第 0 輪原始碼、授權與相容性審查。

後續狀態：上段記錄的是初次審查時的狀態。第 0 輪與初版實作現已完成；衝突處理以 `TECHNICAL_DECISIONS.md` v0.2 為準，最新驗證與待辦見 `VERIFICATION_LOG.md`、`IMPLEMENTATION_PLAN.md`。歷史模型知識、股息與正式實驗的限制仍須在研究中揭露。

## 先解決的問題

1. **價格基準與股息**（藍圖 §5.4、§8、§9）。規格明定使用 raw OHLC、忽略股息，並正確標示為 price-only return；但 SPY 有配息，長期持有與經常空倉的策略受影響不同，四組排名可能隨「是否計入股息」改變。第一版可以保留價格報酬作軟體驗收，但研究報告應增加含股息的敏感度分析，或明確限制結論只適用於 price-only 規則。不要把自動調整過的 OHLC 當作 raw 成交價格；`yfinance` 的 `history()` 目前預設 `auto_adjust=True`，轉接器必須顯式設定並驗證輸出。

2. **共同起點與訊號日尚未定義到可執行程度**（§8.1、§9.1）。「每週最後一個有效交易日」在缺漏資料時可能錯把星期四當星期五；Buy & Hold 的「第一個共同可交易日進場」也可能比其他策略早一天成交。固定交易所日曆、資料缺口政策、每組策略首個決策日、下一開盤成交日、暖機及期末未成交訊號處置。先用一週跨假日和一週缺漏資料的樣本驗證。

3. **Agent Trace 的儲存與 API 契約不完整**（§10–12、§13）。Decision Explorer 要呈現當時 FeatureSnapshot、每個 Agent 的輸入與原始輸出，但 `DecisionRecord` 只有 snapshot ID 與驗證後 JSON；API 也未明定如何取得 snapshot、原始回應、各次模型呼叫和失敗原因。補上不可變的 snapshot/呼叫紀錄及查詢或匯出契約；每筆紀錄需可連到資料雜湊、特徵版本、模型設定、prompt、風控、成交與成本。機密應排除。

4. **歷史 LLM 比較的結論範圍**（§5.2、§9.2–9.3）。遮住日期及關閉搜尋可降低直接洩漏，但不能證明模型從未見過 2019–2025 年市場資訊。2025 年能當本專案開發的保留測試集，不能直接稱為模型知識上的前瞻測試。事先凍結 prompt、模型版本、參數和資料；保存完整呼叫結果並以 Replay 做可重現比較。報告把結果解讀為指定模型與資料上的歷史模擬，不宣稱具備未來預測能力。

5. **四組比較的預算和失敗覆蓋率**（§7.4、§9、§13）。多代理比單代理多兩次呼叫，且超時、無效輸出、預算上限會使交易被跳過；這些都會改變持倉與績效。除 token/美元/延遲外，逐組報告成功決策數、跳過數、失敗原因及曝險時間。若要聲稱是代理架構帶來的改善，另做等推論預算或等呼叫數的比較。

6. **測試規格有一處已被後文修正的矛盾**（§15.2、後附「第一則指令」第 8 項）。§15.2 的「相同交易下，加入成本後的淨績效不得高於零成本結果」只有在訊號、成交數量和估值方式等條件固定時才是適當斷言；完整回測若成本改變下次倉位，直接比較可能變成另一個交易路徑。依後文的較精確要求，測試固定參考開盤價、成交價與數量，逐筆驗證毛損益、滑價影響和手續費只計一次。

## 開發與交付風險

- **MVP 範圍偏大。** 12 週內同時做資料管線、可驗證帳本、四組研究、三 Agent、完整前後端、端對端測試和報告，有較高整合風險。第 1–4 輪先完成一條可從固定 CSV 跑到帳本與圖表的垂直流程，再逐步接入 Agent 與其餘頁面；每輪以可執行證據驗收。
- **資料與模型成本還沒落實。** 目前沒有固定 CSV、來源權利說明、模型提供者、費率快照或呼叫總量估算。第 0 輪應先選定合法可展示的樣本資料，以及 Mock/Replay/API 的邊界和成本上限。
- **工作者重啟與 SQLite 寫入需具體規則。** §11 已要求未完成任務不能永久停在 `RUNNING`，但要定義單工作者鎖、啟動時狀態修復、每次實驗產物的原子寫入及重複提交處理。
- **規格文件與 Git 基礎剛建立。** 本目錄起初是空資料夾且尚非 Git Repository；第 0 輪需確立版本控制、依賴鎖檔、資料/產物忽略規則，才有可靠的 `code_commit` 與實驗追溯。

## 第 0 輪的決策順序

1. 定義資料集來源、raw/adjusted 價格契約、股息處理與可展示授權。
2. 固定交易所日曆、共同起點、暖機、首筆成交與結束邊界。
3. 補齊 Agent 呼叫、FeatureSnapshot、Decision Explorer 的儲存與 API 契約。
4. 明確區分歷史模擬的研究問題、成本公平性和報告中的結論限制。
5. 鎖定通過相容性驗證的套件版本，再列可獨立驗收的工作包。
